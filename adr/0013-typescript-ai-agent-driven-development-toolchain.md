# 0013. AI 駆動開発を支える機械的支援ツールチェーンおよび超高速自律修復サイクルの採用 (0013-typescript-ai-agent-driven-development-toolchain.md)

- **ステータス**: 承認 (Accepted)
- **日付**: 2026-10-03

---

## 1. 背景と解決すべき課題 (Context & Problem)

AI コーディングエージェント（Claude Code / Antigravity / Cursor 等）を活用して開発を進める際、プロンプトで「綺麗に書いてください」「型エラーに注意してください」と人間に頼るような指示を出すと、以下の課題が発生します。
1. **技術的負債の急蓄積 (AI Slop)**: AI が新機能を追加する過程で、使わなくなった古い関数・未使用の export・不要な依存関係がコードベースに放置される。
2. **AI の主観による品質ブレ・タイポ**: プロパティ名やコメントの微細なスペルミス、場当たり的な型キャスト（`as Type`）が混入する。
3. **文字列置換の破壊事故**: 大規模リファクタリング時に AI がテキスト検索置換を行い、構文破壊やインポート不整合を起こす。
4. **過度な禁止の弊害**: ライブラリや技術を頭ごなしに禁止すると、ボイラープレートが増加し開発効率を著しく阻害する。

---

## 2. 決定事項と具現化仕様 (Decision & Specification)

技術を禁止して裁量を奪うのではなく、**「人間や AI の主観・目視に頼らず、機械的ツール（Rust 製超高速ツールおよび AI 支援ツール群）で品質を自動判定・修正・生成する支援ツールチェーン」** を正式採用する。

### 採用する機械的支援ツール群

| ツール名 | 実装 | カテゴリ | 具現化仕様・AI 協業での役割 |
|---|---|---|---|
| **Knip** | Node.js / MCP | コード衛生・デッドコード駆除 | 未使用の export、孤立ファイル、ゾンビ依存を依存グラフから自動検出・一括削除 (`knip --fix`)。Knip MCP 経由で AI に定期掃除を実行させる |
| **Biome** | **Rust** | 超高速フォーマッター & リンター | ESLint / Prettier の 20 倍高速（15ms）。AI 生成直後のインデント崩れや構文違反をミリ秒で自動整形 |
| **typos** | **Rust** | ソースコード特化スペルチェッカー | 変数名、コメント、ドキュメントの誤字脱字をミリ秒で検出。AI が起こしがちな微妙なスペルミスを機械的に撲滅 |
| **ast-grep (`sg`)** | **Rust** | 構造的 AST 検索 & リライト | 正規表現を超えた「構文木パターン」で危険コードを検出・自動修正 |
| **ts-morph** | TS / AST | 決定論的コード一括変換 | TypeScript AST を直接操作し、Branded Types の注入や大規模リファクタリングをプログラム実行 |
| **ts-pattern** | TS / 型安全 | 網羅的パターンマッチング | クイズ進行状態の Discriminated Union に対し、`.exhaustive()` で全ケース網羅を型強制し処理漏れをコンパイルエラー化 |
| **sqlc** | Go | 型安全 SQL コード自動生成 | プレーン SQL から型安全な Go リポジトリを機械生成し、手動パースバグを根絶 |
| **Repomix** | Node.js | AI コンテキスト最適化 | リポジトリ構造とコードを XML/Markdown に 1 ファイル集約し、AI のトークン消費を抑え理解度を向上 |

### AI 自律修復ループ (Self-Healing Loop)
AI エージェントがコードを生成・変更した直後、以下の高速検証パイプラインを実行させ、エラー時はログをプロンプトに戻して自己修正させた上で人間へ提示する。
```
[AI コード生成]
       │
       ▼
1. Biome Check (15ms)    ─── 失敗 ──► `biome check --write` でミリ秒自動整形
       │ 合格
       ▼
2. typos (20ms)          ─── 失敗 ──► `typos -w` でスペルミス自動修正
       │ 合格
       ▼
3. tsc --noEmit (1s)     ─── 失敗 ──► コンパイルエラーログをプロンプトに戻して自己修正
       │ 合格
       ▼
4. Knip Audit (1s)       ─── 失敗 ──► `knip --fix` で AI が散らかしたデッドコードを自動削除
       │ 合格
       ▼
[人間への Pull Request 提出 / レビュー]
```

## 3. 採否の根拠とトレードオフ (Rationale & Trade-offs)

### 品質ガバナンスアプローチの比較検討

| 手法・アプローチ | フィードバック速度 | 人間レビュー負担 | AI の自律性 | 判定 |
|---|---|---|---|---|
| **指示プロンプト依存 (お願いベース)** | なし (人間任せ) | 極大 (毎回手動指摘) | 低い (指示忘れ多発) | **却下**: 破綻 |
| **技術の完全禁止 (裁量を奪う)** | - | 大 (ボイラープレート増加) | 低い (制約が厳しすぎる) | **却下**: トレードオフ大 |
| **機械的ツール支援 (Mechanical Leverage) [採択]** | **超高速 (<2秒で全完了)** | **極小 (ツールが自動判定)** | **極めて高い (ツールで自己修正)** | **採用**: 速度・品質・衛生の最高両立 |

- **決定打**: Rust 製の超高速ツール（Biome, typos, ast-grep）と Knip を組み合わせることで、AI の判断や人間の目視確認を待つことなく、ミリ秒単位で「合っているか間違っているか」を決定論的に判定できる。これにより技術の自由度を奪わずに、極めて高いコード衛生を維持できる。

## 4. 得られる効果と留意点 (Consequences)

### ポジティブな影響 (Positive)
- **AI Slop の自律的排除**: Knip により、機能追加を繰り返しても不要なコードや依存関係が一切残らず、コードベースが常にスリムに保たれる。
- **高速な自己修正**: Biome と typos のミリ秒応答により、AI の思考テンポを崩さずに高品質なコードへ収束。
- **型と構文の厳密性**: ts-pattern と ast-grep により、エッジケースの処理漏れや危険なアンチパターンを機械的に排除。

### 留意点と対策 (Negative & Mitigation)
- **ツールの設定学習コスト**:
  - 対策: `package.json` に `npm run check`（Biome + tsc + typos）および `npm run clean:deadcode`（Knip）としてスクリプト化し、AI および開発者が 1 コマンドで実行できるように抽象化する。
