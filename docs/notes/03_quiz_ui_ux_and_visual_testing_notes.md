# クイズ UI/UX 原則とビジュアル回帰テスト観点 (Note 03)

本ノートは、推し活クイズ UI の設計において発生した失敗（顔被り、文字折り返しバグ、フィードバック埋没）の根本原因を整理し、UI/UX 原則および Playwright ビジュアル回帰テストの観点を永続化するための記録である。

---

## 1. 失敗の分析と根本原因 (Root Cause Analysis)

### 1.1. 顔被り (Face Occlusion)
- **事象**: ドーナツモーダルを開いた際、完全透過にしたにもかかわらず、15 個のカラージュエルと中央ツインスティックがアイドルの顔面（目・鼻・口）を完全に覆い尽くした。
- **根本原因**:
  - モーダルをデフォルトの画面中央配置（`centered: true`）としていた。
  - アイドル公式ポートレート写真は「上部 15% 〜 45%」に顔が配置されている。画面中央に直径 280px の円形 UI を展開すれば、顔面を直撃することは自明であった。
  - 「背景を透明にしたから顔が見える」というエージェントの独善的な判断により、ジュエル自体の物理的な重なりを見落とした。

### 1.2. 文字数バグ (Text Wrapping Bug)
- **事象**: 「エメラルドグリーン」を選択した際、ツインスティック内のバッジで `エメラルドグリー\nン` と不自然な 1 文字改行が発生した。
- **根本原因**:
  - 幅が固定または狭いコンテナ（`maxWidth: 105px` 等）内で、最大文字数（8〜10文字）のカラー名が表示されるケースを想定していなかった。
  - `white-space: nowrap` による折り返し禁止や、文字数に応じた動的フォント縮小（`font-size: clamp` またはスケール調整）が適用されていなかった。
  - Playwright スクリーンショット撮影時、最長文字数のカラーを選択した状態でのレンダリング確認を怠った。

### 1.3. 解答画面の下部埋没 (Feedback Cutoff / Poor Visibility)
- **事象**: 顔を隠す中央モーダルを避けるあまり、回答結果（`InlineFeedbackBar`）を画面の最下端（底辺）に配置した結果、ブラウザ枠外や端末下部に沈みかけ、親指での操作性や視認性がかえって悪化した。
- **根本原因**:
  - 「顔を隠さない」ことと「ユーザーの自然な視線・指の可動域に収める」ことのトレードオフを適切に設計せず、極端に画面下端へ追いやった。
  - 画面全体のレイアウト構造（ビューポート高さ、ヘッダー、写真カード、ボトムバー）の縦方向の配置バランスが崩れていた。

## 2. 推し活 UI/UX 設計原則 (Guiding Principles)

### 2.1. 顔の視認性確保とカバー率基準 (Face Visibility & Coverage)
- **本質的ゴール**: 「目・鼻・口（表情）」がはっきりと視認でき、推しメンの魅力が損なわれないこと。厳密なピクセル単位の絶対非干渉ではなく、定性的な視認性を最優先とする。
- **配置・カバー率の基準**:
  - **表情中心（両目・鼻・口）の保護**: 顔の中心ラインに不透明な大型 UI（ツインスティックの文字板、濃い背景カード等）が重なることを禁止する。
  - **下寄り配置へのシフト**: ドーナツリングやパレットの中心を、画面中央（`y: 50%`）からやや下（胸元・顎下付近、目安 `y: 60%〜65%`）へオフセットさせ、円の上端が顔の目元にかかるのを回避する。
  - **周辺要素の許容**: 髪の毛の端や輪郭周辺にカラージュエルが一部重なることは、表情の視認性を妨げない範囲で許容する。見た瞬間に「誰の顔か・どんな表情かが一目でわかる」状態を合格基準とする。

### 2.2. カラー名テキストの禁則ルール (Text Sizing & Overflow)
- **1 行厳守 (`white-space: nowrap`)**: ペンライト上や選択バッジ内のカラー名は、不自然な文字折り返し（例: `〜グリー\nン`）を絶対に発生させない。
- **文字数に応じた自動スケール**:
  - 5 文字以下（例: 「レッド」「パステルブルー」）: 通常フォントサイズ（12px）
  - 6 文字以上（例: 「エメラルドグリーン」「バイオレット」）: 縮小フォントサイズ（10px〜11px）
  - コンテナ幅に収まらない極端な長文は `overflow: hidden; text-overflow: ellipsis;` を適用する。

### 2.3. 解答フィードバックの配置適正化 (Feedback Positioning)
- **枠外埋没の防止**: 画面底辺（スクロールが必要な枠外）に追いやることを禁止する。
- **ビューポート内完結**:
  - 写真の高さをビューポートからヘッダーおよびフィードバック領域を引いた高さ（例: `calc(100dvh - 120px)`）に自動収容する。
  - フィードバック（正解・不正解表示および「次へ」ボタン）は、親指が届き視線移動の少ない「写真直下または写真下部オーバーレイ」に確実に固定表示する。

## 3. Playwright E2E / ビジュアルテスト観点 (Testing Matrix)

再発防止のため、以下の 3 つの検証観点を E2E テストシナリオに組み込み、機械的および視覚的に検証する。

### 3.1. 最長文字カラーでの折り返し・溢れ検知 (Text Wrapping Check)
- **テスト手順**:
  1. 15 色の中で最も文字数が多いカラー（例: 「エメラルドグリーン」）を左手・右手にそれぞれ選択する。
  2. ペンライト上およびツインスティック選択バッジの DOM 要素を取得する。
- **判定基準**:
  - `scrollWidth <= clientWidth`（文字が枠外に溢れていないこと）。
  - 要素の高さが 1 行分（例: 24px 以下）であり、`\n` による複数行への改行が発生していないこと。

### 3.2. 顔中心の定性的視認性・遮蔽検知 (Face Clearance Check)
- **テスト手順**:
  1. ドーナツモーダルを開いた状態のスクリーンショットを撮影する。
  2. 写真の上部顔領域（高さ 20% 〜 45%、幅中央 50%）と、ツインスティック等の不透明 UI のバウンディングボックス（BoundingBox）を比較する。
- **判定基準**:
  - 不透明な情報ボックス（文字板）が顔の主要領域（目・鼻・口）と重複していないこと。
  - ドーナツの中心 `top` 座標が画面中央（50%）よりも下方にオフセット（例: 58% 〜 65%）されていること。
  - スクリーンショットレビューにおいて、「表情がはっきりとクリアに視認できるか」を定性的に目視合意すること。

### 3.3. 解答フィードバックのビューポート内完全収容 (In-Viewport Audit)
- **テスト手順**:
  1. クイズに回答し、正解または不正解のフィードバックバーを表示させる。
  2. フィードバックコンテナおよび「次へ」ボタンの `getBoundingClientRect()` を取得する。
- **判定基準**:
  - `bottom <= window.innerHeight` かつ `top >= 0`（スクロールせずとも画面内に完全に収まっていること）。
  - ボタンが押しやすい位置（下部セーフエリアから適度なマージンを確保）にあること。

## 4. 実装修正計画 (Fix Proposals)

### 4.1. ドーナツモーダルの下寄り配置シフト (Y-Offset)
- `Modal` の完全中央配置（`centered`）を調整し、円形コンテナを中心から下方（胸元・胴体位置、`translateY(60px〜80px)`）へシフトさせる。
- これにより、円の上端がアイドルの顎下〜胸元に位置し、目・鼻・口を含む顔全体がクリアに視認可能となる。

### 4.2. 文字折り返しの完全解消 (Text Scaling & White-space)
- ツインスティック中央のカラー名表示に `white-space: nowrap` を強制。
- 文字数に応じた動的フォント縮小（6 文字以上は `fontSize: 10px`, `letterSpacing: -0.02em`）を導入し、最長の色名「エメラルドグリーン」でも 1 行ですっきりと枠内に収める。
- 写真上のペンライトラベル（左手・右手）にも同様に折り返し禁止を適用する。

### 4.3. 解答フィードバックバーの配置最適化 (Viewport Fitting)
- `InlineFeedbackBar` の高さをスリム（48px 程度）に維持し、ビューポート最下部から少し浮かせた位置（`bottom: 16px`、または写真下部情報バーの上）にマージン付きで配置する。
- 画面全体のコンテナ高さを `100dvh` に収め、下部バーが出現しても写真が画面外に押し出されず、スクロール不要で完結するレイアウトに調整する。

### 4.4. Playwright E2E テストの拡充
- `frontend/e2e/screenshot.spec.ts` に「最長文字色（エメラルドグリーン）の選択状態」および「下寄りドーナツ展開時のスクリーンショット」を追加。
- 撮影された画像をアーティファクトでレビューし、定性的な顔の視認性と文字崩れゼロを確実に検証する。
