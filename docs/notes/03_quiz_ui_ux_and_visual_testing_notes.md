# クイズ UI/UX 原則とビジュアル回帰テスト観点 (Note 03)

本ノートは、推し活クイズ UI の設計において発生した失敗（顔被り、文字折り返しバグ、フィードバック埋没）の根本原因を整理し、UI/UX 原則および Playwright ビジュアル回帰テストの観点を永続化するための記録である。

---

## 1. 失敗の分析と根本原因 (Root Cause Analysis)

### 1.1. 顔被り (Face Occlusion)
- **事象**: ドーナツモーダルを開いた際、完全透過にしたにもかかわらず、15 個のカラージュエルと中央ツインスティックがアイドルの顔面（目・鼻・口）を完全に覆い尽くした。
- **根本原因**:
  - モーダルをデフォルトの画面中央配置（`centered: true`）としていた。
  - アイドル公式ポートレート写真は「上部 15% 〜 45%」に顔が配置されている。画面中央に直径 280px の円形 UI を展開すれば、顔面を直撃することは自明であった。
  - 「背景を透明にしたから顔が見える」というエージェントの独善的な判断により、ジュエル自体の物理的な重なりを見落とした。

### 1.2. 文字数バグ (Text Wrapping Bug)
- **事象**: 「エメラルドグリーン」を選択した際、ツインスティック内のバッジで `エメラルドグリー\nン` と不自然な 1 文字改行が発生した。
- **根本原因**:
  - 幅が固定または狭いコンテナ（`maxWidth: 105px` 等）内で、最大文字数（8〜10文字）のカラー名が表示されるケースを想定していなかった。
  - `white-space: nowrap` による折り返し禁止や、文字数に応じた動的フォント縮小（`font-size: clamp` またはスケール調整）が適用されていなかった。
  - Playwright スクリーンショット撮影時、最長文字数のカラーを選択した状態でのレンダリング確認を怠った。

### 1.3. 解答画面の下部埋没 (Feedback Cutoff / Poor Visibility)
- **事象**: 顔を隠す中央モーダルを避けるあまり、回答結果（`InlineFeedbackBar`）を画面の最下端（底辺）に配置した結果、ブラウザ枠外や端末下部に沈みかけ、親指での操作性や視認性がかえって悪化した。
- **根本原因**:
  - 「顔を隠さない」ことと「ユーザーの自然な視線・指の可動域に収める」ことのトレードオフを適切に設計せず、極端に画面下端へ追いやった。
  - 画面全体のレイアウト構造（ビューポート高さ、ヘッダー、写真カード、ボトムバー）の縦方向の配置バランスが崩れていた。


---

## 2. 推し活 UI/UX 設計原則 (Guiding Principles)

### 2.1. 顔の視認性と全体の調和基準 (Balanced Face Visibility)
- **絶対回避の罠からの脱却**: 「絶対に1pxも被らないこと」だけを目的に極端に画面下へ追いやると、不自然な余白やレイアウト破綻を招く。
- **バランス基準**:
  - 表情（目・鼻・口）の中心エリアを覆わなければ、適度な高さでのモーダル展開は許容する。
  - ドーナツの直径を適切にスリム化（240px程度）することで、顔を覆わずに画面全体と調和させる。
  - モーダル展開時は、背面のペンライトを半透明フェードさせ、画面内のペンライト多重重複ノイズを解消する。

### 2.2. カラー名テキストの禁則ルール (Text Sizing & Overflow)
- **1 行厳守 (`white-space: nowrap`)**: ペンライト上や選択バッジ内のカラー名は、不自然な文字折り返し（例: `〜グリー\nン`）を絶対に発生させない。
- **文字数に応じた自動スケール**:
  - 最長文字色「エメラルドグリーン」でも 1 行ですっきりと収まる動的フォントサイジングを適用する。

### 2.3. 解答フィードバックの視認性設計 (Luminous Feedback Design)
- **一瞬で伝わる正解表現**:
  - 単なる黒丸＋文字の詰め込みを廃止。
  - 実際のペンライトのように鮮やかに発光するツインピル／ミニスティックにより、視線を奪わずに正解の2色がパッと脳に飛び込んでくるUIとする。
- **ビューポート内完結**:
  - 写真カード直下にスッキリ収まり、スクロール不要で親指タップが可能な位置に配置する。

## 3. 並行レビュー可能な解答 UI アーキテクチャ

UI の使い心地を実機で即座に比較できるよう、ヘッダーから以下の 3 種類を切り替え可能にする。

1. **`anchor` (アンカー追従型・C案)**:
   - タップしたペンライト（写真右下）の真上にコンパクトなカラーサークルがふわりと展開。顔や中央に一切干渉しない手元完結型。
2. **`donut` (洗練ドーナツモーダル)**:
   - 直径 240px で顔を避けた適正位置に展開する、ゲーム感あふれる円環モーダル。
3. **`grid` (パレットグリッド)**:
   - 画面下部に常時 15 色が並ぶクラシックな選択肢。

---

## 4. 実装計画 (Implementation Plan)

1. **ヘッダーに 3 つの inputMode 切替を実装**:
   - `inputMode: 'anchor' | 'donut' | 'grid'`
2. **アンカー追従型ポップオーバーコンポーネントの新規作成**:
   - `AnchorColorPicker.tsx`
3. **ドーナツモーダルのリファクタリング**:
   - 直径 240px へのスリム化、背面ペンライトのフェード制御。
4. **発光感のある解答フィードバックバーの改善**:
   - `InlineFeedbackBar.tsx` の発光ツインピル化。
5. **Playwright E2E テストでの並行撮影**:
   - アンカー追従型、ドーナツ型、解答バーをそれぞれキャプチャしてレビュー。
