# 不変識別子規約 (typeid-guard)

> **管轄 ADR**: [ADR-0001](../../../adr/0001-surrogate-key-typeid-uuidv7.md), [ADR-0006](../../../adr/0006-domain-schema-and-typeid-structure.md)

本スキルは、TypeID（プレフィックス + UUIDv7）によるサロゲートキーの強制と、自然キーの排除を統制する。

## 絶対遵守ルール (Invariants)

1. **自然キーの主キー利用・URL利用の絶対禁止**:
   - メンバー名（漢字・ローマ字）、グループ名、カラー名等の自然キーを、データベースの主キー（PK）、API の URL パス、画像ファイル名に用いてはならない（同姓同名、改名、新グループ追加で参照が破綻するため）。
2. **公式 TypeID プレフィックスの厳守**:
   - すべてのエンティティ ID は、以下の公式プレフィックスから開始すること。

| プレフィックス | エンティティ種別 | 例 |
|---|---|---|
| `grp_` | グループ (Group) | `grp_019245a1...` |
| `col_` | ペンライトカラー (Color) | `col_019245a2...` |
| `mem_` | メンバー (Member) | `mem_019245a3...` |
| `quiz_` | クイズ設問 (QuizQuestion) | `quiz_019245a4...` |
| `usr_` | ユーザー (User) | `usr_019245a5...` |
| `ans_` | 回答ログ (AnswerLog) | `ans_019245a6...` |

3. **アセットファイル命名の連動**:
   - メンバーの顔写真・画像ファイル名は必ず `mem_<uuid>.webp` とし、差し替え時も新 UUID を付与して旧ファイルを上書きしないこと (Ref: ADR-0008)。

---

## チェックリスト（モデル・API設計時）

- [ ] 新規テーブル・モデルの主キーが `id: ID`（TypeID）になっているか
- [ ] プレフィックスが公式一覧（`grp_`, `col_`, `mem_` 等）に一致しているか
- [ ] URL パスやクエリパラメータに名前文字列ではなく TypeID が使われているか（例: `/api/v1/members/:id`）
- [ ] グループや期生が Enum や const でハードコードされず、外部キー（`group_id`）として設計されているか
